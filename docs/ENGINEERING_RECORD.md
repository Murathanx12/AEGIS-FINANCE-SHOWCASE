# Engineering record

The project is an evolving research implementation, not a finished investment product. This is a selective public account of the work and what its evidence means.

## Workstreams

| Workstream | Implemented direction | What still needs evidence |
| --- | --- | --- |
| Source acquisition | Market/news/filing/revision collectors, source records and document handling | Complete relevant body access and source-to-consumer joins |
| Hypotheses and forecasts | Explicit mechanisms, falsifiers, original clocks and horizon-specific ledgers | Prospective repeatability and valid aligned inputs |
| Decisions | Ranking, sizing, decision contracts and risk constraints | Appropriate calibration and authorized activation |
| Paper evaluation | Account marks, own-window benchmarks, controls and dated reporting | Independent cost-inclusive execution evidence and longer records |
| Attribution | Regret records, ablations and attempts to trace source contribution | Qualified comparisons with available original evidence |
| Optimus | Persistent notes, retrieval, source audits, skill libraries and MCP tools | Every client must demonstrate retrieval and actually apply the guidance |

## Lessons retained

- A successful collection command can still produce an empty or incomplete source record. Coverage and failure state must be explicit.
- A missing price, document or aligned input is unavailable, not zero. Silent replacement contaminates downstream analysis.
- Forecast clocks must remain original. Reprocessing an old record is not a new point-in-time forecast.
- A stored article is not proof that a model read it or used it. Attribution needs a chain of source and consumer evidence.
- Simulator, broker paper, historical replay and prospective records answer different questions. Their numbers cannot be pooled casually.
- A selected winning experiment is useful evidence over its window; selection after the fact and the trial population remain part of the record.
- Tests, a merged branch and a deployed UI are different from a verified scheduled change. Existing financial history should remain preserved.
- Persistent guidance only helps if the next agent retrieves and reads it. The design restoration exposed a workflow failure even though the original record was still retrievable.

These lessons summarize checked engineering records. They do not reproduce the private operational corpus or publish personal account comparisons.
